How Phases 1–3 actually work.

Sign in → create a project → open it → give it a memory. This page teaches the whole path — frontend and backend — file by file, so you can read, change, and extend it. Everything here is built and working in apps/web.

Frontend (apps/web/src/features, shared) Backend (apps/web/src/server, app/api)
00

Run it (today, no database needed)

The backend uses an in-memory store until you set MONGODB_URI, so it runs instantly.

# from apps/web npm install npm run dev # http://localhost:3000 # you'll land on /signin → enter any email → /projects # create a project → open it → add a memory note

The request lifecycle

Every feature follows this same path. Learn it once and the whole app makes sense.

FRONTEND
Component

A screen calls a hook (e.g. useProjects()).

→
FRONTEND
React Query

The hook fetches & caches from the API.

→
BACKEND
Route handler

app/api/v1/... validates + checks session.

→
BACKEND
Repository

Reads/writes the store (Mongo or in-memory).

→
FRONTEND
Render

Data returns; UI shows it (or loading/empty/error).

Two kinds of state, never mixed: server data (the project list) lives in React Query; pure UI state (which dialog is open) lives in Redux (projectsSlice.ts). That one rule keeps everything clean.

03

Phase 2 — Authentication

A real httpOnly cookie session (the secure part), with a simple email sign-in. Your email maps to a stable workspace, so your data is yours and persists.

Phase 2Files & what each doesDONE
server/auth/session.ts # getSession / writeSession / clearSession + email→workspace app/api/v1/auth/route.ts # GET me · POST sign-in · DELETE sign-out features/auth/SignInScreen.tsx # the sign-in UI app/signin/page.tsx # /signin route (redirects in if already signed in) app/projects/page.tsx # server-guarded: no session → redirect /signin
  • How scoping works: every projects/notes query takes session.workspaceId, so one workspace can never read another's data.
  • Guarding pages: a Server Component calls getSession() and redirect("/signin") if absent — the page never renders for signed-out users.
  • To productionize: swap the email sign-in for magic-link/OAuth and sign/encrypt the cookie. Everything else stays the same.

Phase 3 — Project Memory (seed)

A project's first memory: timestamped notes, scoped to (workspace, project). This is the seed the full Memory Engine grows from.

Phase 3Files & what each doesDONE
server/repositories/notes.repo.ts # Note store, Mongo + in-memory app/api/v1/projects/[id]/notes/route.ts # GET list · POST add (checks project ownership) features/project-workspace/notes.ts # useNotes / useAddNote (React Query) features/project-workspace/ProjectWorkspaceScreen.tsx # open project + memory panel app/projects/[id]/page.tsx # /projects/:id route, server-guarded

Opening a project (ProjectCard → router.push("/projects/:id")) loads the workspace, re-themes to the project's domain, and shows its notes. Add a note → POST …/notes → it's remembered and re-listed instantly.

05

Key concepts (plain language)

Route handler

A file named route.ts under app/api/… that exports GET/POST/etc. It's your backend endpoint — runs on the server, talks to the database, returns JSON.

Repository pattern

One place that knows how to read/write a kind of data. Routes call the repository; the repository hides whether it's Mongo or in-memory. Swap storage → routes don't change.

In-memory fallback

When MONGODB_URI isn't set, the repository keeps data in a JS Map for the session. Lets you build & demo with zero database setup; flip to Mongo by setting one env var.

Session cookie

A small httpOnly cookie the browser sends on every request. The server decodes it to know who you are and which workspace to scope to. The browser can't read it (safer).

React Query

Manages server data: fetching, caching, loading/error states, and refetching after a change (invalidateQueries). You never store server data in Redux.

Redux slice

Holds only UI state. createSlice = initial state + small reducers. Read with useAppSelector, change with dispatch(action()). That's the whole model.

06

Switch to a real database

No code change — just configure MongoDB and restart.

# apps/web/.env.local MONGODB_URI=mongodb://localhost:27017 MONGODB_DB=founderos # restart — repositories now read/write real collections: # projects · project_notes (indexes created automatically)

Everything else is identical. The repository sees the env var and uses the Mongo implementation; the routes, hooks, and UI are unchanged. That's the payoff of the repository seam.
